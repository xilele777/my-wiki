---
title: TypeScript 和 JavaScript 的主要差异是什么？
---
TypeScript (TS) 与 JavaScript (JS) 的主要差异在于，**TypeScript 是 JavaScript 的一个“超集”**，它在后者基础上添加了一套**静态类型系统**。

简单来说，**任何合法的 JavaScript 代码，在 TypeScript 中同样有效**，但 TypeScript 引入的静态类型检查是其核心区别。你可以把 JavaScript 看作是灵活的动态语言，而 TypeScript 则在此基础上增加了“类型安全”的保障。

以下是它们的主要区别概览：

| 特性维度 | JavaScript (JS) | TypeScript (TS) |
| :--- | :--- | :--- |
| **核心定位** | 动态脚本语言，灵活易用 | JS的超集，增加了静态类型系统 |
| **类型系统** | **动态类型**：变量类型在运行时确定，可随时改变 | **静态类型**：变量类型在编译时确定，类型错误在编码阶段即可发现 |
| **错误检查** | **运行时**：类型错误只有在代码实际执行时才会暴露 | **编译时**：在代码编译为JS的过程中就会进行类型检查，提前拦截错误 |
| **执行方式** | **解释执行**：可直接在浏览器或Node.js中运行 | **需编译**：需要通过编译器(`tsc`)转译为纯JavaScript后才能执行 |
| **开发工具** | 基础语法提示和自动补全 | 强大的智能提示、代码导航、自动重构等 |
| **学习曲线** | 较低，对初学者友好 | 较高，需要学习和掌握类型系统 |
| **适用场景** | 小型项目、快速原型开发 | 中大型项目、企业级应用、长期维护的项目 |

---

### 核心差异：类型系统

这是两者最本质的区别。

*   **JavaScript 的动态类型**：变量没有固定的类型，可以在程序运行过程中被赋予不同类型的值。例如：
    ```javascript
    let price = 100; 
    price = "99.99"; // 合法，但可能导致后续计算错误
    ```
    这种灵活性在小项目中很方便，但在大型项目中，一个不经意的类型变化就可能埋下难以追踪的Bug。

*   **TypeScript 的静态类型**：变量在声明时就需要（或可以通过类型推断）明确其类型，此后类型不可更改。
    ```typescript
    let price: number = 100; 
    price = "99.99"; // 编译时报错：类型“string”不能赋值给类型“number”
    ```
    这种“强制性”将潜在的类型错误扼杀在编码阶段，极大地提升了代码的健壮性。

### 错误检测与代码质量

由于类型系统的不同，两者发现错误的时机也截然不同。

*   **JavaScript**：**错误暴露在运行时**。很多类型相关的错误只有在代码实际运行到那一行时才会抛出，可能导致程序崩溃。
*   **TypeScript**：**错误拦截在编译时**。在你编写代码或保存文件时，IDE就能根据类型定义给出实时错误提示。编译时，类型错误会直接阻止编译过程。研究显示，使用TypeScript可以将运行时错误率降低90%以上。

### 开发体验与工具支持

*   **JavaScript**：编辑器只能提供基础的语法高亮和有限的代码补全。
*   **TypeScript**：由于拥有明确的类型信息，编辑器能提供**更强大的智能提示、安全的代码重构（如重命名变量时自动更新所有引用）、精准的代码导航**等高级功能。这能让开发者在编写代码时就能获得即时反馈，效率更高。

### 语法特性与执行方式

*   **语法特性**：TypeScript 引入了许多 JavaScript 目前没有或支持不完善的高级特性，如**接口 (Interface)、泛型 (Generics)、枚举 (Enum)、访问修饰符 (public/private)** 等。
*   **执行方式**：这是另一个关键区别。**JavaScript 是解释型语言，可以直接运行**。而 **TypeScript 需要编译**，它自带的编译器 (`tsc`) 会将所有 `.ts` 文件编译成标准的 `.js` 文件，这个过程会**移除所有的类型注解**，最终在浏览器或Node.js中运行的仍然是纯JavaScript代码。

### 总结与选择建议

选择哪种语言，取决于项目的具体需求：

*   **选择 JavaScript，如果**：
    *   项目规模较小，或处于快速原型验证阶段。
    *   团队对JavaScript非常熟悉，且不想引入额外的编译构建流程。
    *   项目是一次性的脚本或简单的页面交互。

*   **选择 TypeScript，如果**：
    *   项目是**中大型应用**，或预期会长期维护和迭代。
    *   项目有**多人协作**，类型系统可以作为“活文档”，减少沟通成本并防止因不了解代码而引入错误。
    *   项目使用 **React、Vue 3、Angular** 等现代前端框架，这些框架都对 TypeScript 有极佳的支持。
