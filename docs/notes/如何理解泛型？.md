---
title: 如何理解泛型？
---
理解 TypeScript 泛型（Generics），你只需要搞懂一句话：

> **泛型就是“类型的变量”或“类型的函数参数”。**

就像函数接受一个**值参数**（比如 `function fn(num)` 里的 `num`），让函数能处理不同的数值一样；泛型接受一个**类型参数**（比如 `<T>`），让组件（函数、接口、类）能处理不同的类型。

如果你之前用 `any` 来“放水”取消类型检查，那泛型就是“**精准的活水**”——它既能适应各种类型，又能牢牢记住你传入的具体类型，并帮你检查到底。

下面我用 3 个层次帮你彻底吃透它：

---

### 1. 核心铁律：泛型是“保留关系的绳索”

假设你要写一个函数，返回传入的参数本身（恒等函数）。

- **用 `any` 写**：输入 `"hello"`，TS 只知道返回 `any`（丢失了类型）。后续调用 `.length` 还得靠猜。
- **用泛型写**：输入 `"hello"`，TS 知道返回 `string`。输入 `123`，TS 知道返回 `number`。

```typescript
// 用 any：类型失忆了
function returnIt(value: any): any {
  return value;
}
const a = returnIt("hello"); // a 的类型是 any，TS 帮不了你了。

// 用泛型：类型被记住了
function returnIt<T>(value: T): T {
  return value;
}
const b = returnIt("hello"); // b 的类型被推断为 "hello" (string)
const c = returnIt(123);     // c 的类型被推断为 123 (number)
```

> **记忆点**：泛型像一根**绳索**，绑定了参数的类型和返回值的类型。用 `any` 绳子就断了，用泛型绳子始终连着。

---

### 2. 关键动作：“占位”与“填坑”

**定义时**（写代码）：你不知道未来用户会传什么类型，先用 `T`、`U`、`K` 这些字母占个坑。

```typescript
// 定义时：T 是个占位符，代表"未知的类型"
function getFirst<T>(arr: T[]): T {
  return arr[0];
}
```

**使用时**（调用时）：TS 自动根据你传的值推断出具体类型，把 `T` 的坑填上。

```typescript
// 使用时：TS 自动把 T 推断为 number
const num = getFirst([1, 2, 3]); // num 是 number

// 你也可以手动指定（虽然不必要）
const str = getFirst<string>(["a", "b"]); // str 是 string
```

---

### 3. 给泛型“上枷锁”（约束 extends）

如果泛型太自由，你想操作 `.length` 属性，但万一用户传了个 `number` 进来，没有 `length`，代码就崩了。

这时候用 `extends` 关键字给泛型加个**约束（Constraint）**，规定它必须符合某种形状。

```typescript
//  报错：类型 "T" 上没有属性 "length"
function getLength<T>(arg: T): number {
  return arg.length; 
}

//  加上约束：T 必须拥有 length 属性
function getLength<T extends { length: number }>(arg: T): number {
  return arg.length; 
}

getLength("hello"); // 字符串有 length
getLength([1,2,3]); // 数组有 length
getLength(123);     // 报错！number 没有 length
```

> **记忆点**：`extends` 就是给泛型划定的“活动范围”，确保它具备你需要的特征。

---

### 4. 现实开发中最实用的两个场景

光看理论容易忘，这两个场景你 100% 会遇到：

#### 场景一：封装 API 请求（接口泛型）
后端返回的数据结构通常都有 `code`、`msg` 和 `data`，但 `data` 里面的内容千变万化。这时泛型是绝配：

```typescript
// 定义通用的 API 响应结构
interface ApiResponse<T> {
  code: number;
  msg: string;
  data: T; // data 的具体类型由调用时决定
}

// 获取用户信息（data 是 User 类型）
interface User { name: string; age: number; }
function fetchUser(): Promise<ApiResponse<User>> { ... }

// 获取商品列表（data 是 Product[] 类型）
interface Product { id: number; price: number; }
function fetchProducts(): Promise<ApiResponse<Product[]>> { ... }
```

#### 场景二：React Hooks（如 useState）
你在 React 里写 `useState`，其实就在用泛型：

```typescript
// useState 是一个泛型函数，<number> 指定了 state 的类型
const [count, setCount] = useState<number>(0); 
// 如果 TS 能推断出来，也可以省略 <number>，直接写 useState(0)
```

### 5. 高级技巧（面试加分项）

- **多个类型参数**：可以像函数传多个参数一样，传多个类型 `T, U, K`。
  ```typescript
  function merge<T, U>(obj1: T, obj2: U): T & U {
    return { ...obj1, ...obj2 };
  }
  ```

- **默认类型**：给泛型一个默认值，类似于函数参数的默认值。
  ```typescript
  interface Page<T = any> { // 如果不传类型，默认就是 any
    data: T;
  }
  ```

- **`keyof` 约束**：确保传入的 key 必须是对象中存在的键。
  ```typescript
  function getProperty<T, K extends keyof T>(obj: T, key: K) {
    return obj[key];
  }
  ```

---

### 终极记忆口诀

把下面三句话刻在脑子里：

1. **`<T>` 就是声明一个“类型变量”**，看到它就想起 `function fn(arg)`。
2. **泛型是“保鲜膜”**，包裹着你的类型，确保输入和输出的类型一致性不被丢失。
3. **`extends` 是“门槛”**，跨不过这个门槛的类型，泛型不伺候。
