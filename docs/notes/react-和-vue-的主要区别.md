---
title: React 和 Vue 的主要区别
---
**1. 编程范式（底层哲学）**

- **React**：函数式编程，强调**数据不可变（Immutability）**，UI = f(state)。必须显式调用 `setState` 触发更新。
- **Vue**：响应式编程，数据**可变（Mutable）**，直接操作 `state.count++` 即可，底层代理自动感知变化。

**2. 数据更新机制（最关键底层差异）**

- **React**：**拉（Pull）**。不知道数据何时变，只能通过 `setState` 触发**组件树自上而下全量重建**（重新执行 render），生成新虚拟DOM后 Diff 找差异。
- **Vue**：**推（Push）**。Vue2 用 `Object.defineProperty`，Vue3 用 **`Proxy`** 劫持数据。`get` 时收集依赖（谁用了这个数据），`set` 时**精准推送**更新到最小组件，直接更新视图。

**3. 更新粒度与性能优化**

- **React**：**组件级更新**。状态变化导致父组件 render 时，默认所有子组件跟着重渲染，必须手动使用 `React.memo`、`useMemo`、`useCallback` 来“砍掉”不必要的渲染。
- **Vue**：**靶向更新**。因为依赖收集精确到具体属性，组件能精准知道自己该不该变，**天然自带性能优化**，几乎不需要手动优化。

**4. 虚拟DOM（VDOM）定位**

- **React**：**核心基石**。VDOM 是声明式 UI 和跨平台（React Native）的根本，所有更新必经 VDOM Diff。
- **Vue**：**增强辅助**。VDOM 主要用于模板编译和跨平台（Weex），但由于有响应式兜底，VDOM 的 Diff 压力远小于 React。

**5. 写法与模板（开发者体验）**

- **React**：**JSX**（JavaScript 的语法扩展）。逻辑与 UI 紧密耦合，灵活度极高，但要求强 JS 功底，插值用 `{ }`。
- **Vue**：**Template（模板）**。基于 HTML 扩展（`v-if`、`v-for`），上手门槛低，更接近原生 Web 标准。虽然也支持 JSX，但非主流。

**6. 数据变更方式**

- **React**：**不可变数据**。必须用展开运算符或 `Immer` 生成新对象（如 `setList([...list, newItem])`），便于回溯调试（Time Travel）。
- **Vue**：**可变数据**。直接修改原对象（如 `list.push(newItem)`），Proxy 能捕获变更并更新视图，更符合直觉。

**7. 逻辑复用方式**

- **React**：**Hooks**（`useState`、`useEffect`）。重度依赖闭包和**调用顺序**（不能写在 if 里），依赖数组管理复杂，容易产生**闭包陷阱**。
- **Vue**：**Composition API**（`ref`、`reactive`）。本质依赖 Proxy 拦截，**不依赖调用顺序**，无需依赖数组，逻辑组织起来更像普通变量，TS 兼容性极佳。

**8. 生态与家族**

- **React**：**轻核社区化**。核心只管 UI，路由（React Router）、状态（Redux/Zustand）需社区选型，选择多且灵活。**大厂背书，中后台复杂应用、跨端（React Native）统治力强**。
- **Vue**：**官方全家桶**。路由（Vue Router）、状态（Pinia）由官方维护，配置极简，开箱即用。**国内 C 端业务、管理后台普及率极高**。

**9. 使用场景与上手曲线**

- **React**：曲线陡峭。概念多（JSX、Hooks、高阶组件、副作用），需要思考“如何优化渲染”，适合大型复杂、多人协作的项目。
- **Vue**：曲线平滑。文档友好，新手也能快速写出可用页面，适合中小型项目或追求极致开发效率的团队。
